# Тесты product-v1

`test_file_mode_owner_adapter.py` — механические тесты
`product/adapters/product-file-mode-owner-check-v2.py`:

- emitted bash не содержит мутирующих примитивов;
- fail-closed отказ для `owner` / `group` / `owner_group`, для op вне
  `eq` / `bits-clear`, для маски `0000`, для не-четырёхзначного значения,
  для относительного locator, для locator с кавычкой, переводом строки
  или подстановкой, для control_id вне `[A-Za-z0-9._-]`;
- связка adapter JSON <-> реализация <-> семантический контракт по SHA-256;
- поведение на фикстурах: VALUE (в том числе setuid-биты и режим 0000),
  NOT_FOUND только при доказанном отсутствии, ERROR для висячей ссылки,
  цикла ссылок, непроходимого родителя и отсутствия `stat`;
- целевой файл не изменяется.

Два ordinary-user permission regressions выполняются и при запуске suite от root: дочерний Bash запускается с непривилегированными UID/GID, поэтому relevant assertion не может молча скрыться за EUID root.

`test_sysctl_adapter.py` — механические тесты
`product/adapters/product-sysctl-check-v2.py` и `product/ADAPTER-REGISTRY.tsv`:

- отдельная product identity, historical `sysctl-check-v1` не изменяется;
- только `parameter.kind=sysctl`, `locator=sysctl`; current v2 поддерживает
  `eq` и source-faithful integer lower-bound `ge`;
- dotted sysctl key преобразуется в `/proc/sys/...`;
- целое значение нормализуется как signed base10 без ведущих нулей;
- VALUE/PASS, VALUE/FAIL, NOT_FOUND и ERROR;
- каждый ERROR fixture проверяет непустой стабильный reason-code `domain:reason`; production `ERROR` с `-` запрещён, при этом `NOT_FOUND` сохраняет `-`;
- ошибка чтения не создаёт неструктурированный stderr (P-01);
- registry содержит current строки для `sysctl`, `file-mode-owner` и
  `kernel-cmdline`; все contract/binding/implementation SHA совпадают.

`test_product_generator.py` — regression предыдущего `generate-product-check-v1.py`, current adapter semantics и current unified CLI v2:

- current `CONTROL-MANIFEST.tsv` определяет population динамически и проверяется по SHA;
- `ADAPTER-REGISTRY.tsv` является единственным источником выбора adapter;
- registry SHA для semantic contract / binding / implementation проверяются;
- для `ERROR` проверяется не только форма `domain:reason`, но и exact branch→reason binding на воспроизводимых failure-mode fixtures;
- deterministic render одинаковых входов даёт одинаковые bytes;
- current controls маршрутизируются по `parameter.kind` через tracked `ADAPTER-REGISTRY.tsv`;
- synthetic `file-mode-owner` подтверждает dispatch через второй adapter;
- unknown kind отклоняется fail-closed;
- generated CHECK проходит `bash -n`, `--help`, `--build-info`,
  `--provenance` и usage-RC;
- generated bytes проходят defense-in-depth scan известных mutating tokens; scan не считается формальным доказательством отсутствия произвольной shell-mutation capability; APPLY ограничен `SRC-0001_ONLY` и проверяется отдельными usage/dry-run/report/registry regressions; пользовательский `--restore` отсутствует, operational RESTORE не планируется к реализации.
Регрессия текущей population также закрепляет точную семантику `sysctl eq` для `SRC-0030`, `SRC-0031`, `SRC-0036`–`SRC-0039` и `SRC-0040 / fs.suid_dumpable=0`. `SRC-0034` состоит из одного control `kernel.randomize_va_space=2`; «после тестирования» — порядок действий администратора, не объект проверки.

Текущий sysctl regression покрывает `eq` и unbounded signed-integer `ge`; `ge` используется только для source clauses, которые явно задают lower bound.

### Ретроспективные regressions FSTEC-40

Текущий набор tests дополнительно фиксирует robustness-границы всех 40 строк: для SRC-0006 group-class parent `wx` даёт ERROR (одного mode недостаточно, чтобы доказать применимость principal/ACL), однозначный other `wx` даёт FAIL, а write-without-search не ошибочно трактуется как право записи directory-entry. Набор tests также фиксирует независимо воспроизведённые ретроспективные counterexamples: для SRC-0001 NUL/CR во входных данных состояния учётной записи даёт ERROR; для SRC-0003 проверяются любой GID группы wheel (номер 10 не требуется), поле пароля группы, не являющееся предикатом, и неоднозначность pre-rule `auth/-auth` PAM short-circuit/include; для SRC-0005 каталог с совпадающим mode даёт ERROR; для SRC-0011 canonical direct-only population `/var/spool/cron/crontabs` исключает посторонние объекты parent spool и соседние `atd`, сохраняя fail-closed обход admitted root; для SRC-0012 population исполняемых файлов root PATH исключает обычные неисполняемые данные; для SRC-0013 SUID/SGID-файлы на `nosuid` остаются в population; для SRC-0014 проверяются service accounts, не перечисленная `.zsh_history`, Bash `.bash_login`, обнаружение config/autoload/history Nushell, стандартных config/history Xonsh/Elvish и отсутствие захвата `.vimrc`; для SRC-0015 — домашние каталоги service accounts. Эти tests являются negative-control evidence исправленных current adapter identities.
