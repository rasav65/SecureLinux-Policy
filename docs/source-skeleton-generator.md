# Универсальный по индексу генератор блока `source:`

Этап 5 roadmap вводит канонический способ построения блока `source:` записи
контроля.

## Контракт

Для поддерживаемой строки source index
`tools/source_skeleton_generator.py` формирует:

- `index_id`;
- `doc_id`;
- `doc_sha256`;
- `locator`;
- канонический `quote`;
- `quote_sha256`;
- `norm`.

Путь к индексу задаётся явно через CLI (`--index`); `index/source-v4` является
только текущим значением по умолчанию. Поэтому генератор использует общий
контракт source index, а не жёстко заданный путь только для FSTEC.

Для поддерживаемых `unit_kind` генератор является **единственным нормативным
производителем** `source:`. Этап 6 roadmap теперь обеспечивает это механически:
каждый закоммиченный control регенерируется и побайтово сравнивается через
`checker/source-parity-v1/source_block_regeneration_parity.py`.

## Текущая область извлечения

Текущая population source index и набор `unit_kind` читаются машинно из
`index/source-v4/SOURCE-INDEX.tsv`; документ не закрепляет их live-counts.

Эта версия поддерживает `numbered-position`, `general-numbered-position` и
`numbered-subpoint`.
Step 7B вводит единый typed-result API `classify_row()`: каждая строка current
index получает ровно одно состояние `EXACT | REFUSED | UNSUPPORTED` и стабильный
machine-readable `reason_code`. Exact/refused/unsupported population вычисляется
при каждом regression-прогоне и не пинуется числами или списком identities в
документации. `REFUSED` используется только для явно типизированного deliberate
refusal; integrity/index failures остаются исключениями и завершают обработку
fail-closed. `quote_anchor_ready != YES` проверяется до `UNSUPPORTED`.

`SRC-0001 / 2.1.1` больше не относится к refused population: для него принят
только exact pinned trailing page token `3`; generic bare-integer stripping
по-прежнему запрещён. Актуальный refused set является test-owned machine truth
`tests/source-skeleton-v1/test_source_skeleton_generator.py`, а не ручным
документационным списком.

Остальные неподдерживаемые `unit_kind` не получают заявленной автоматической
генерации цитаты. Их population также определяется текущим source index.

## Правило границ для `numbered-position`

Токен, похожий на номер, становится границей структуры только тогда, когда он
является допустимым структурным продолжением предыдущего принятого маркера:
первым потомком, следующим соседом либо следующим соседом одного из предков.

Это не позволяет значениям вроде `kernel.dmesg_restrict=1.` и номерам
документов/страниц молча превращаться в границы нормативной единицы.

Для `fstec-linux-2022` отдельно закреплено узкое правило для **конечного**
горизонтального разделителя PDF: точный токен `________________________`
удаляется только если он является последним токеном одновременно всего
нормализованного корпуса и извлечённой последней numbered-position. На
закреплённой странице 7 PDF это нижняя горизонтальная линия после пункта
`2.6.6`, а не нормативный текст. Внутренние последовательности подчёркиваний
и такой же токен не в EOF никогда не удаляются.

## Правило границ для `numbered-subpoint`

В fstec-configuration-2026 заголовок раздела записан как `N.` с точкой, а
подпункт — как `N.M` без точки после номера. Кандидаты обоих видов проходят
тот же фильтр структурного продолжения. Подпункт заканчивается перед
следующим маркером той же или меньшей глубины.

Закреплены три исключения. Маркер сразу после токена `таблице ` или
`Таблица ` — ссылка на таблицу, а не граница. Строка `SRC-0091` напечатана
как `8.4` внутри раздела 9 и получает отказ `SOURCE_NUMBERING_MISMATCH`.
Конечная линия `____________________________` удаляется по правилу конечного
разделителя. Если в подпункте есть отдельный целочисленный токен (возможен
номер страницы), строка получает отказ `BARE_INTEGER_INSIDE_UNIT`: номер
страницы не удаляется без закреплённого правила строки.

## Правило границ для `general-numbered-position`

Локатор записан как `<секция>:<порядковый номер>`, а не как точечный
путь. Порядковый номер выбирает N-й маркер верхнего уровня того же
принятого outline, поэтому границы единиц определяет тот же фильтр
структурного продолжения.

Единица заканчивается перед следующим маркером верхнего уровня.
У последней единицы секции такого маркера нет, и без отдельного правила
она дошла бы до конца корпуса, вобрав в себя приложения. Поэтому её
границей служит один точный закреплённый терминатор секции. Он обязан
встречаться ровно один раз и после начала единицы; отсутствие, дублирование
или положение не позже начала единицы дают отказ, а не приближение.

## Цепочка доверия

Перед выдачей блока генератор проверяет fail-closed:

- точный контракт полей source index и уникальность `index_id`;
- `quote_anchor_ready=YES`;
- закреплённый SHA `normalizer-v1.py` и его selftest;
- выбор recovered/extracted корпуса по `text_quality`;
- SHA источника и метаданные нормализации из manifest;
- SHA нормализованного корпуса;
- каноничность цитаты по `norm-v1`;
- наличие цитаты как подстроки выбранного нормализованного корпуса.

Физическая проверка закреплённого PDF остаётся обязанностью Gate 1. Генератор
намеренно не содержит жёстко заданного каталога PDF FSTEC, чтобы входной индекс
оставался универсальным для разных policy layers.

## Регрессионные доказательства

`tests/source-skeleton-v1/test_source_skeleton_generator.py` постоянно
проверяет:

- все current controls, число которых берётся из `CONTROL-MANIFEST.tsv`,
  воспроизводятся побайтово;
- typed `EXACT/REFUSED/UNSUPPORTED` population вычисляется по всей current index
  population при каждом прогоне, а не пинуется документацией;
- explicit refused set и его `reason_code` сверяются fail-closed с test-owned
  machine truth;
- normalizer SHA mismatch, corpus/quote integrity failure и неизвестное typed
  state не преобразуются в `REFUSED`/`UNSUPPORTED`;
- `SRC-0001` отдельно подтверждается как exact pinned page-furniture exception,
  а не как refused identity;
- известный hash цитаты `SRC-0018`;
- точную границу конечного `SRC-0040 / 2.6.6`: footer-line исключается,
  а два отрицательных fixture доказывают отсутствие общего underscore-strip;
- работу с альтернативным путём к индексу;
- отказ при дублировании index;
- отказ при `quote_anchor_ready != YES`;
- отказ при изменённом normalizer;
- отказ при повреждённом hash нормализованного корпуса.

Сам генератор блока `source:` не закрывает строки FSTEC source index.
Актуальный нормативный прогресс не дублируется вручную здесь и читается из
`index/source-v4/PROGRESS.txt` / сгенерированный `docs/fstec-coverage.md`.
