# Source-block regeneration parity

Roadmap step 6 closes the gap between the canonical source skeleton generator
and committed control records.

## Invariant

For every committed control:

1. `source.index_id` must resolve in the selected common-contract source index;
2. the row's `unit_kind` must be supported by the canonical generator;
3. the generator must rebuild the complete seven-field `source:` block;
4. the regenerated bytes must equal the committed `source:` block bytes.

Anything else fails closed.

The parity checker is:

`checker/source-parity-v1/source_block_regeneration_parity.py`

It accepts explicit `--index` and `--controls` paths. The current defaults are
`index/source-v4/SOURCE-INDEX.tsv` and `controls`, but the checker itself is not
restricted to a FSTEC-only index path.

## Current closure evidence

Current result:

All five controls therefore have mechanically enforced regeneration parity.

The source generator itself remains scoped to one of the thirteen current
`unit_kind` values (`numbered-position`). If a committed control refers to an
unsupported kind, parity reports `UNSUPPORTED` and fails; it never silently
skips the control.

Permanent negative regression covers:

- edited `quote`;
- edited `quote_sha256`;
- edited `locator`;
- unsupported `unit_kind`;
- absent index row;
- duplicated/malformed top-level `source:` block.
